# Project: model-adapters

Project Status: development
Versioning: none

## Project and User Directives and Rules (Mandatory)

- `model_adapters.json` is the single source of truth, consumed by BlazeAI and FluxAI. It is
  generated by `scripts/generate.py` from models.dev and `overrides.json` and never edited by hand;
  run the generator (it validates) before every push. The GitHub Action is the CI.
- This repository is the only place where model data is added or changed. FluxAI and BlazeAI
  never edit it and never keep their own model facts; a model change starts here.
- A new protocol value needs support in the consumers first: both reject an unknown protocol.
- No endpoint, URL, or credential fields in the catalog.
- Every content change increments `revision`; breaking schema changes bump `schema_version` and
  must be coordinated with both consumers.

## Overview

Public data repository (MIT) with the model/protocol catalog, generated from models.dev plus a
hand-written overrides layer. Schema and procedure: `README.md`.

## Operating Model

Applications fetch the raw file over HTTPS (ETag), validate the fields they use, and cache the
last valid copy. Both resolve their models from it: FluxAI hub sources name only a catalog model
and a reasoning level, and the relay takes protocol, `max_tokens`, levels, and Lite from here.

Model facts come from models.dev: a provider with a `models_dev` block in `overrides.json` takes all
models of that models.dev provider (or only the listed ones), and a model models.dev drops leaves the
catalog. `overrides.json` holds what needs a person: providers models.dev lacks (Codex OAuth),
live-tested corrections, and consumer options. Change a model: `git pull`, edit `overrides.json`, run
`scripts/generate.py`, commit, push. A daily GitHub Action (also on push and manual dispatch) runs
the tests and the generator and commits a changed catalog (`specs/implemented/catalog-generator.md`).

## Source Authority

`README.md` defines the schema; `scripts/validate.py` enforces it. Specifications index:
`specs/specs.md`.

## Project Map

- `model_adapters.json` — the catalog.
- `overrides.json` — provider list and order, models.dev sources, hand-kept models and corrections.
- `scripts/generate.py` — generator (stdlib); `scripts/test_generate.py` — its tests.
- `scripts/validate.py` — strict local validator (stdlib).
- `.github/workflows/generate.yml` — daily generation, tests, and catalog commit.
